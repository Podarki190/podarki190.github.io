# Сайт-каталог «Лазер Клин» — lazerklin.ru

Статический сайт-каталог настенных часов (тот же ассортимент, что на WB, ~5400 товаров).
Работает с 14.08.2026, на своём домене с 18.08.2026. Хостинг GitHub Pages, сборка
GitHub Actions ежедневно в 3:00 UTC. Заказ — звонок/WhatsApp/Telegram или «Купить на WB».

Каталог тянется прямо с WB Content API (`WB_API_TOKEN` в секретах репозитория).
Гугл-таблица из сборки сайта убрана 13.08.2026 — тексты сайта это тексты карточек на WB.

## Грабли, которые уже наступили — не повторять

- **Пуш только так.** Работа идёт в worktree на ветке `worktree-wall-clocks-catalog-build`.
  `git push origin master` толкает старую master и молча отвечает «Everything up-to-date».
  Правильно: `git push origin worktree-wall-clocks-catalog-build:main`,
  потом `git -C <главный репо> merge --ff-only worktree-wall-clocks-catalog-build`.
- Пути к ассетам **только относительные** — сайт может жить в подпапке Pages.
- `CNAME` кладёт сама сборка (`build.js`), иначе каждая выкладка сбрасывает домен.
- Главная ограничена 300 товарами (`HOME_LIMIT`), полный список давал 4,9 МБ.
  Поиск при этом ищет по всему каталогу через `catalog.json`.
- Темы берутся из первых 300 знаков описания, не из названия. Словарь в `src/themes.js`.
- VK отдаёт страницы в windows-1251 — при парсинге декодировать явно.

## Задолженность

Приём заказов пишет в гугл-таблицу, а хранение персональных данных в Google противоречит
ч.5 ст.18 152-ФЗ. Решено переезжать на Яндекс Формы. Правовой раздел уже написан под Яндекс
и до переезда помечен рамкой «вступает в силу после перевода».

Детали устройства, тем, услуг и блога — в моей памяти:
`wb-catalog-site-handoff`, `wb-blog-pipeline`, `vk-autopost-api`.
