# Каталог-витрина настенных часов — дизайн

Дата: 2026-08-11

## Цель

Публичный сайт-каталог настенных часов (тот же ассортимент, что продаётся на Wildberries), без встроенной оплаты. Заказ — звонок, WhatsApp, Telegram или переход на карточку товара на WB. Обновляется автоматически, без ручной работы пользователя после первичной настройки.

## Источники данных

- **Google Sheets Web App** (уже существует, см. память `wb-google-sheets-webapp`) — `action: read_rows` отдаёт все строки таблицы карточек часов.
- **WB Content API** (`https://content-api.wildberries.ru`) — используется только для получения реальных ссылок на фото по `Артикул WB` (nmID). Токен предоставит пользователь на шаге настройки, хранится как секрет GitHub Actions, в репозиторий не попадает.

**Почему не эксель-выгрузка WB:** в гугл-таблице уже есть `Артикул WB` (реальный nmID) почти у 2500 строк — этого достаточно, чтобы не просить пользователя вручную выгружать и присылать эксель на каждое обновление. Ручная выгрузка противоречила бы требованию «обновляется само раз в 24 часа».

## Правило отбора товара в каталог

Строка попадает в каталог **тогда и только тогда**, когда `Артикул WB` — валидное число (карточка реально создана на WB), **и** WB API вернул хотя бы одно фото по этому nmID. Колонка «Статус ИИ» не используется как фильтр (она заполняется вручную и ненадёжна — часто пустая даже у реально живых карточек).

Товары без фото или без Артикула WB в каталог не попадают (никогда не показываем карточку без картинки).

## Данные карточки товара

Из таблицы используется только: `Наименование`, `Артикул WB`. Цена и фото — не из таблицы:

- **Фото** — из WB Content API по nmID (первое/основное фото).
- **Цена** — не берётся из таблицы. Отображается статично и одинаково для всех товаров: ~~7000 ₽~~ **1890 ₽**, подпись «Доставка по всей России Бесплатная». Значение — константа в шаблоне сайта, меняется в одном месте при необходимости.

## Устройство сайта

Статический сайт, без бэкенда:
- `products.json` — генерируется скриптом сборки, содержит массив товаров (название, nmID, url фото, все 4 ссылки уже готовы).
- `index.html` + `app.js` (ванильный JS, без фреймворка) — при загрузке страницы подгружает `products.json`, рендерит карточки, `loading="lazy"` на картинках.
- Строка поиска — фильтрует уже загрученный массив по подстроке в названии (без сервера, без пагинации — 2500 карточек в DOM браузер тянет нормально при ленивой загрузке картинок).

## Сборка и публикация

- Репозиторий на GitHub, хостинг — **GitHub Pages** (бесплатно).
- **GitHub Actions**: workflow с `schedule` (раз в 24 часа) + `workflow_dispatch` (ручной запуск по кнопке в интерфейсе GitHub) — читает таблицу → фильтрует → тянет фото с WB API → генерирует `products.json`/`index.html` → публикует на GitHub Pages.
- Секреты (`GITHUB_SECRETS`, не в коде): секрет Google Sheets Web App, токен WB API.

## Обработка ошибок

- Таблица недоступна при запуске сборки → шаг падает, сайт остаётся на предыдущей опубликованной версии (GitHub Pages не перезаписывается при неуспешном workflow).
- WB API не вернул фото для конкретного nmID (ошибка/рейт-лимит) → этот товар пропускается в текущей сборке (не весь процесс), появится в каталоге при следующем успешном обновлении.

## Тестирование

Один самопроверяющий скрипт (`test_generate.js`, на `assert`, без фреймворков) на тестовых фикстурах (несколько строк таблицы + фиктивный ответ WB API) проверяет:
- товар без Артикула WB не попадает в `products.json`;
- товар без фото не попадает в `products.json`;
- ссылки WhatsApp/WB/Telegram/tel собираются в правильном формате;
- цена в выводе всегда `1890` со зачёркнутой `7000`, независимо от `Цена` в таблице.

## Первичная настройка (вне кода, шаг при внедрении)

- Помощь пользователю в регистрации аккаунта на GitHub (аккаунта пока нет).
- Создание репозитория, включение GitHub Pages (Source: GitHub Actions) в настройках репозитория.
- Добавление секретов (Google Sheets secret, WB API token) в настройки репозитория.
